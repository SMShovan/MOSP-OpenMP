# Results

Measurements of the `fix/correctness-perf` branch (`bin/mosp` built at
`09e74c1`; the later commit `e5719f6` does not touch it) against the
original code (`baseline-2026-09`). The fixes and optimizations are
described in [CHANGES.md](../CHANGES.md).

- **(a) compute**: the parallel compute of the K SOSP updates and of Steps
  2-3 (combined graph + its SOSP), the region the papers time. For the
  original code: the propagation loops plus the BFS post-passes of the
  K + 1 SOSP calls plus the OpenMP membership map of the combined graph,
  without its sequential Step 1 and its adjacency-list building. The new
  code's (a) includes Step 1 and the combined-graph construction, but not
  applying the batch and building the reverse graph ("prepare").
- **(b) end to end**: from reading the text inputs (CSR, batch, initial
  trees) to writing all outputs; the same files for both codes.

## Method

- **Hardware:** Xeon Gold 6258R (28 cores, 56 threads), 124 GB RAM; g++
  12.2. The machine is shared with other jobs; the runs of this campaign
  did not overlap with each other.
- **Threads:** 28, pinned to the physical cores
  (`OMP_NUM_THREADS=28 OMP_PROC_BIND=close OMP_PLACES=cores`).
- **Repetitions:** median of 3 runs unless noted.
- **Original code:** `baseline-2026-09` built with the system g++ and the
  original flags (as-is: no optimization) and with `-O3`, driven by a thin
  harness that calls the original functions (K x `parallelSOSPUpdate`, then
  `parallelCombinedGraph`) on the same input files and adds stage timers
  (the OpenMP variant of `optimization_study/prototypes/mosp_kernel`,
  `mospBench`).
- **Inputs:** the same files as in MOSP-CUDA's results (SuiteSparse
  roadNet-PA, roadNet-CA, rgg_n_2_20_s0, road_usa; K = 3 uniform weights in
  [1, 100], seed 12345; source 0; batches generated by `bin/mospPrep
  changes` with seed 777):
  - *safe*: 50K changes, 50% deletions, minus the deletions that would
    disconnect a vertex (`--safe`);
  - *unsafe*: the same 50K batch unfiltered (about 7% of the deletions cut
    vertices off on the road graphs);
  - *local*: 10K changes (50% deletions, connectivity-safe) inside a BFS
    ball of 110-200 hops (`--local`; 104K-121K vertices);
  - K sweep: roadNet-CA widened to 4 objectives, 50K safe batch.
- **Validation:** the original harness compares distances with Dijkstra
  (PASS in every run with a reference); the new code was run with
  `--validate --canonicalize` on every graph and batch kind (all trees and
  the MOSP tree identical to Dijkstra).

overstated by up to ~30%; per objective the new update is 24x faster than
the low-load value (7.47 s vs 308 ms).

## OpenMP vs CUDA (new code, identical inputs)

CUDA: MOSP-CUDA `bin/mosp` of the same branch on an RTX A5000. Both produce
byte-identical trees.

| graph | batch | OpenMP (a) | CUDA (a) | CUDA / OpenMP speedup (a) | OpenMP (b) | CUDA (b) |
|---|---|---:|---:|---:|---:|---:|
| roadNet-PA | safe | 63.2 ms | 18.5 ms | 3.4x | 645 ms | 794 ms |
| roadNet-PA | unsafe | 63.6 ms | 17.8 ms | 3.6x | 645 ms | 747 ms |
| roadNet-PA | local | 95.9 ms | 39.7 ms | 2.4x | 626 ms | 842 ms |
| roadNet-CA | safe | 110 ms | 33.7 ms | 3.3x | 1.17 s | 1.25 s |
| roadNet-CA | unsafe | 109 ms | 33.6 ms | 3.3x | 1.14 s | 1.25 s |
| roadNet-CA | local | 74.8 ms | 21.0 ms | 3.6x | 1.03 s | 1.18 s |
| rgg_n_2_20_s0 | safe | 166 ms | 83.0 ms | 2.0x | 1.30 s | 1.63 s |
| rgg_n_2_20_s0 | local | 241 ms | 227 ms | 1.1x | 1.65 s | 1.80 s |
| road_usa | safe | 1.32 s | 377 ms | 3.5x | 12.9 s | 12.2 s |
| road_usa | unsafe | 1.31 s | 378 ms | 3.5x | 13.6 s | 12.0 s |
| road_usa | local | 707 ms | 179 ms | 3.9x | 11.2 s | 11.0 s |

The GPU is 2.0-3.9x faster on (a) except for the rgg local batch (1.1x).
End to end both are dominated by text I/O; the CUDA run also pays ~0.2 s of
context creation plus the host-device copies, so this build is slightly
faster end to end on the three smaller graphs.

## Reproducing

```
bench/prepare.sh roadNet-CA.mtx g 3          # CSR, initial trees, 50K batches
bench/run.sh g g/changes_50000_50_safe 3     # pins 28 threads, reports medians
```
